Mach

A fast Gmail and Google Calendar client for macOS.

Keyboard-driven, with several accounts in one stream and an agent that has real tools over your mail and calendar. It talks to the Gmail and Google Calendar APIs. There is no IMAP and no support for other mail providers.

macOS only · Build from source · MIT · github.com/bborn/mach
What it does

Every view renders from a local SQLite database. Opening a thread is a local read: under a millisecond, and it works with the network off. Sync runs in the background and writes into that database, and the UI reacts to the changes.

Local data
A 12-month backfill per account, then incremental history sync from a stored watermark. Nothing in the UI waits on Google.
Search
Gmail's operator syntax, parsed as you type and compiled to SQL against an FTS5 index. from:, has:attachment, older_than:2m, quoted phrases, OR and - all work. Most queries answer in single-digit to low-tens of milliseconds against a 61,000-message store.
Keyboard
Gmail's own keys: J K to move, E to archive, B to snooze, C to write, R to reply, G I for the inbox. ⌘K for search and commands, ? for the full list. ⌘Z undoes over a stack that does not expire.
Several accounts
One ordered stream, with a colour bar per account on every row. A reply goes out from the account the thread arrived on.
Calendar
Day, week and month views, with drag to create and drag to move. Opening an event shows its guests and their answers, the recurrence rule, reminders, and the Meet link if it has one.
Attachments
Fetched, cached, opened and saved, with inline images rendered in the message. Image types come from the file's magic bytes rather than the sender's Content-Type, and executables are refused.
Notifications
New mail raises a notification and a Dock badge. The rule is narrow: unread, in the inbox, not from you, and either in Gmail's Personal category or continuing a thread you have written to.
An agent with real tools
Every action in Mach is a typed command in Rust, and those commands are the agent's whole tool surface. It runs on the Claude Code CLI when one is installed, so it uses the subscription you already have and needs no API key. Sending mail and anything that reaches a guest waits for your approval; the rest is undoable and lands in the same log as the actions you took by hand. ⌘K can also hand a thread to an external agent you configure.
Plugins
Third-party actions run in a sandbox with no network, no file access and no Google credentials. A plugin acts by dispatching the same commands your keyboard does, within the capabilities you granted it, so ⌘Z undoes its work too.
What it doesn't do

None of this is planned.

  • No IMAP or SMTP. Mach uses the Gmail API.
  • No other providers. No Outlook, Fastmail, iCloud, or generic mail.
  • No mobile, no web, no Windows, no Linux. Refresh tokens live in the macOS Keychain and the UI is a WKWebView.
  • No teams and no sharing. It is a single-user client.
  • No packaged build, no releases, no auto-update. You build it from source.
Install

  1. Prerequisites

    • macOS, Apple silicon or Intel
    • Rust stable, with the Xcode command line tools
    • Bun
    • A Google account you can create a Cloud project with
    • For the agent, either the Claude Code CLI or an Anthropic API key. Mach uses the CLI when it finds one.

  2. Bring your own Google OAuth app

    Mach ships no credentials. Every user registers their own Google Cloud project and OAuth client, because this app is not submitted to Google for verification and never will be. Hand skills/mach-setup/SKILL.md to a coding agent that can drive a browser and it will walk the console with you: the project, the two APIs, the consent screen, a Desktop app client, the six scopes, publishing, and writing .env.local. It stops and hands the keyboard back for your password and for accepting the User Data Policy. The same file works as a click-by-click checklist if you would rather do it yourself.

    Google will warn you about the app. The first time you authorise each account it shows "Google hasn't verified this app". Click Advanced → Go to Mach (unsafe) and continue. It happens once per account.

    Publish the app to In production even though it is unverified. Left in Testing, Google expires every refresh token after seven days, and you re-authorise every account every week.

  3. Build and run

    git clone https://github.com/bborn/mach
cd mach
bun install
bun run tauri dev

    Then ⌘K → Add account. If the credentials are missing the app still boots and the window still paints; the UI tells you it cannot add an account.

The state of it

This is one person's mail client, built for their own use and published in case someone else finds it useful. It is not a product, there is no support, and there are no releases. The author uses it every day.

Expect rough edges. There is no packaged build or auto-update, no first-run onboarding beyond adding an account, and marketing-email HTML renders imperfectly. cargo test and bunx vitest run are the safety net; there is no end-to-end suite. ⌘K → Send feedback captures the window and files the result into the author's own task runner, which you probably do not have. The command reports that it could not file the task; the capture and annotation half still works.

The architecture and the reasoning behind it are written down in the repo, in the design record and the README.
